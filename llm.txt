## Command contract

Install: python3 -m venv .venv && .venv/bin/pip install .
Interactive: .venv/bin/ios-anywhere (no arguments, terminal only; arrow-key menus produce the existing CLI arguments)
Help: .venv/bin/ios-anywhere --help
Setup: .venv/bin/ios-anywhere setup (Godot by default; refuses existing config/toolchain)
Unattended setup: .venv/bin/ios-anywhere setup --sdk-source mirror --yes (explicit unofficial SDK choice)
Expo setup: .venv/bin/ios-anywhere setup --engine expo (Ubuntu 24.04 only, 20 GiB free; experimental, not yet clean-machine validated)
Doctor: .venv/bin/ios-anywhere --engine expo doctor
Godot doctor: .venv/bin/ios-anywhere --engine godot doctor
Expo build: .venv/bin/ios-anywhere --engine expo --project /path/to/app --credentials /private/credentials.json build --output /path/to/new.ipa
Godot build: .venv/bin/ios-anywhere --engine godot --project /path/to/game --bundle-id com.example.game --credentials /private/credentials.json build --output /path/to/new.ipa
Verify: .venv/bin/ios-anywhere verify /path/to/app.ipa
Install: .venv/bin/ios-anywhere install /path/to/app.ipa --udid DEVICE_UDID

Global options precede subcommands. --project is required for build/bundle; --credentials for build; --bundle-id for Godot build/bundle. Existing output files are rejected. bundle generates resources without signing. There is no built-in submit command.

Optional Apple upload uses EAS Submit from an EAS-configured application project:
npx eas-cli submit --platform ios --profile production --path /path/to/AppStore.ipa
This is an external submission service, not a local compiler or proof of Apple approval. Read README.md for credentials, profile, and destination requirements. Do not upload unless the user authorizes submission.

## Implementation map

- ios_linux/cli.py: arguments and orchestration.
- ios_linux/config.py: toolchain and cache configuration.
- ios_linux/setup.py: staged toolchain setup, checked downloads, SDK import, native link check.
- ios_linux/setup_expo.py: Ubuntu 24.04 Swift/Node/Ruby/macros/overlay recipe and native smoke check.
- ios_linux/expo.py and ios_linux/godot.py: isolated backend workflows.
- ios_linux/signing.py: credentials, signing, verification, and final output.
- ios_linux/scripts/: compiler helpers, graph export, and verifier.
- tests/: SDK-free unit tests.

The canonical config is ios-anywhere/config.json under XDG_CONFIG_HOME (or ~/.config). Fall back to ios-linux/config.json only when the canonical file is absent; explicit --config wins. Never migrate or overwrite existing files automatically. Toolchain/cache paths remain values from the selected config. The ios-linux command alias, ios_linux Python module, and IOS_LINUX_* variables remain supported.

## Operational rules

Use explicit user-authorized projects, credentials, output paths, and devices. Never hardcode personal apps or use a previously built app as a hidden dependency. Keep original sources unchanged during builds. Do not expose secrets in logs, commits, arguments, or documentation. Never commit SDKs, toolchains, profiles, keys, IPAs, or project caches.

Stop builds before deleting their temporary outputs. Identify exact cache paths; preserve source, credentials, durable toolchains, and requested final artifacts. Check free disk space before large builds. Do not change repository visibility to enable hosting.

Only Linux x86_64 is validated. Expo SDK 54 and Godot 4.5.1 minimal examples ran on iPhone. Generic widgets/extensions are unsupported. Godot C# and GDExtensions are rejected. Godot sets version/build to 1.0/1. CS Callouts was uploaded to Apple with a Linux-built executable and an asset catalog reused from an EAS build of the same app (docs/validation.md). Apple processing, TestFlight availability, App Review, and publication remain unverified. Precompiled Assets.car is still required for the documented App Store path. Clean-machine bootstrap and universal compatibility are not established.

Verification checks local integrity/signatures, not Apple trust/revocation or runtime behavior. Distinguish build, verification, installation, launch, feature testing, upload, Apple processing, and review approval. Report only observed results.

## Checks

python3 -m unittest discover -s tests -v
python3 -m compileall -q ios_linux tests
git diff --check

Documentation-only changes need link and command checks, not a new device build. Keep documentation in English. Do not run real signing, installation, submission, or expensive builds just to edit documentation.

Signing setup: ios-anywhere --config /path/to/config.json signing-setup --output /private/new-signing-folder
Interactive Apple login/team selection, existing distribution P12 validation, device selection/registration, and Ad Hoc profile creation. Explicit confirmation precedes Apple mutations. Never creates/revokes certificates. One app/device, no capability configuration. Output credentials contain a password; keep private. Failed runs preserve partial files/resources.
Saved devices: ~/.config/ios-anywhere/devices/saved.json (XDG_CONFIG_HOME respected). Install menu selects a saved name/UDID or saves a new one; every app/extension profile must include the selected UDID. Local device saving is not Apple registration. USB trust/pairing is still required.
Signing helper tests: node --test tests/signing-setup.test.cjs (Node and OpenSSL required; fake Apple API, temporary test keys only).
