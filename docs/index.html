How it works

One command, two backends

Example command — not a build running in the browser. Paths and identities below are fictional.

Explicit project

No project is selected implicitly — --project is always required, regardless of the working directory.

External toolchain

Compilers, SDKs and credentials live outside the repository and are configured separately by the user.

Separate cache

Each project uses a separate cache, isolated from the durable toolchain. Delete it only when builds are stopped; the next build regenerates dependencies and products.

The terminal explains how to obtain credentials, then uses existing signing credentials without displaying their contents. It runs the Expo build command, prepares dependencies, generates the JavaScript bundle and Hermes bytecode, compiles native modules, links, signs, and verifies the IPA. The installation command reaches 100%. On the mirrored iPhone, the user opens the sample app and increments its counter to 17. This demonstrates this sample on this device; it does not establish compatibility with every project or App Store approval.

Installation

Clone, venv, pip

Python 3.11+, Node/npm, OpenSSL and Pillow are required. Installing the package does not install SDKs, compilers or Apple credentials — prepare the toolchain separately.

git clone https://github.com/rodriguesabner/ios-anywhere.git
cd ios-anywhere
python3 -m venv .venv
.venv/bin/pip install .
. .venv/bin/activate
ios-anywhere --version
ios-anywhere doctor
ios-anywhere --engine godot doctor

Prepare the external toolchain as described in docs/toolchain.md.

Verify, install, submit

Take your IPA to the next step

Use a device provisioning profile that includes your iPhone for direct installation. Keep certificates, passwords, and profiles outside version control.

ios-anywhere verify /path/to/MyApp-01.ipa
ios-anywhere install /path/to/MyApp-01.ipa --udid YOUR_UDID

Upload to App Store Connect

From your app's EAS-configured project, submit a production IPA with an App Store distribution profile and a new build number. Configure the destination app and your Apple authentication in the submission profile.

npx eas-cli login
npx eas-cli submit --platform ios --profile production --path /path/to/MyApp-AppStore.ipa

This uses EAS Submit as an external upload service, not EAS Build. ios-anywhere has no built-in submit command. An Ad Hoc IPA is not a store submission artifact. Apple processing, TestFlight availability, and App Review remain separate steps; precompiled asset catalogs are still required. See the full submission guide.

FAQ

Limits, no sugarcoating

Do I need a Mac to run this flow?

No, in a prepared Linux environment. The toolchain and SDKs are external prerequisites; the Python package does not install them.

Does it use EAS Build?

No. The Expo backend uses local tools from the Expo ecosystem. Submitting the IPA to a store is a separate step.

Do I need an Apple certificate?

Yes. The CLI signs with your credentials and respects the provisioning profile's restrictions — it does not replace a certificate.

Does it work with any app?

No. The backends cover the documented paths. Projects with different native features need their own validation.

Can I submit to the App Store?

Upload to Apple has been tested with CS Callouts, using a Linux-built executable and an asset catalog reused from an EAS build of the same app. Apple processing, TestFlight availability, App Review, and publication remain unverified; precompiled asset catalogs are still required.
